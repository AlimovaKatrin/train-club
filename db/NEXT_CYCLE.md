# Цикл тренировок 9–16

Для последующих изменений №3–9 используй [обновление до версии 3](WORKOUT_UPDATE.md): `npm run db:seed:next-cycle -- --update-3-9 --apply`. Исходный режим ниже создаёт версию 2 и не переписывает опубликованные планы.

Состав хранится в `db/seeds/next-cycle.json`. Каждая из восьми новых тренировок содержит шесть основных упражнений по два рабочих подхода. Замены имеют собственные планы. Для боковой планки сохранён диапазон **20–30 секунд на каждую сторону**.

## Что изменится

Скрипт `scripts/seed-next-cycle.mjs` создаёт версию 2 — «Силовые · 16 тренировок». В неё копируются тренировки №1–8 из текущей персональной программы: названия, порядок, основные упражнения, замены, инструкции и планы подходов остаются прежними. Затем добавляются №9–16. Повторяющиеся упражнения используют прежние идентификаторы справочника, поэтому предыдущие результаты сохраняются.

Исходная версия остаётся в базе неактивной; её упражнения и планы не редактируются. Сохранённая история по-прежнему связана с исходными тренировками, её можно просматривать и исправлять.

- Текущий номер сохраняется. После №8 будет №9.
- Если в старой версии последней завершена №8, а очередь уже вернулась к №1, новая программа продолжится с №9.
- После №16 очередь возвращается к №9: повторяется только новый цикл.
- Скрипт очистки истории по-прежнему возвращает очередь к №1; после первого полного прохождения снова повторяются №9–16.

## Запуск

Нужны Node.js 24, установленные зависимости и уже загруженная персональная программа №1–8. Подключение читается только из выбранного env-файла, по умолчанию `.env.production.local`. Переменная `DATABASE_URL` терминала не используется.

```sh
# Проверка, текущий/будущий номер и список необходимых миграций; без записи:
npm run db:seed:next-cycle

# Применить миграции, загрузить цикл и переключить активную программу:
npm run db:seed:next-cycle -- --apply

# Для локальной базы:
npm run db:seed:next-cycle -- --apply --env-file=.env.local
```

Перед переключением заверши текущее занятие в старой версии либо начни его заново после переключения. Черновики старой версии остаются на устройстве, но сохранить их как новое занятие после смены активной программы нельзя. Сохранённую историю переключение не меняет.

Запуск на рабочем сервере выполняй в окно обслуживания: миграция `003_next_cycle.sql`, обновлённая версия приложения и активация программы должны быть согласованы. Новому коду нужна миграция №003, а для корректного перехода 8→9 и 16→9 нужен новый код. Если миграции выполняются отдельно, сначала примени их, затем обнови приложение и запусти загрузку цикла. Сам скрипт применяет недостающие миграции автоматически при `--apply`.

Миграции, копирование, добавление и переключение выполняются одной транзакцией. При ошибке изменения откатываются. Повторный запуск проверяет существующую версию без сброса очереди, добавления дубликатов или изменения истории. При другой активной программе, несовместимых единицах учёта или неоднозначном названии упражнения скрипт останавливается.

Старые команды `db:seed:personal` и `db:seed:production` предназначены для первоначальной программы №1–8. Для расширения используй `db:seed:next-cycle`.
