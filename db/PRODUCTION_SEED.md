# Засеивание рабочей базы

Скрипт `scripts/seed-production.mjs` загружает согласованный план A/B: **8 тренировок, 11 упражнений с заменами, 144 плановых подхода с учётом всех вариантов**. В каждой тренировке упражнение №4 — сгибание ног сидя, замена — лёжа, оба по 2 × 12–15. Расширенный справочник и историю из Google Sheets он не импортирует.

Нужны Node.js 24, установленные зависимости (`npm ci`) и подключение PostgreSQL с правами на миграции и запись данных.

## Запуск

В `.env.production.local` должна быть строка `DATABASE_URL` рабочей базы. Файл исключён из Git. Скрипт читает именно этот файл; `DATABASE_URL` из терминала и `.env.local` не используются. Параметры TLS берутся из строки подключения, проверка сертификата скриптом не отключается.

Из корня проекта:

```sh
nvm use
# Проверить подключение, текущие данные и необходимые миграции без записи:
npm run db:seed:production

# Применить миграции и загрузить программу:
npm run db:seed:production -- --apply
```

Явная проверка и другой файл подключения:

```sh
npm run db:seed:production -- --check --env-file=/absolute/path/production.env
npm run db:seed:production -- --apply --env-file=/absolute/path/production.env
```

Перед работой выводятся сервер, порт и имя базы, без логина и пароля. В результате `seeded` означает, что программа загружена; `already_loaded` — что существующая программа сохранена без сброса очереди. Проверка без записи не гарантирует права на изменение схемы: окончательная проверка выполняется при `--apply`.

## Что делает скрипт

- В новой базе создаёт схему; в существующей применяет недостающие миграции, включая изменяемую длительность пилатеса и бокса.
- Загружает программу в пустую базу либо активирует её вместо демо, если силовой истории ещё нет. Демо остаётся в базе неактивным.
- Сохраняет записи бокса и пилатеса с их длительностью. Запись пилатеса на 30 минут автоматически не создаётся.
- Повторный запуск проверяет существующую активную программу A/B и сохраняет текущий номер тренировки и историю.
- Останавливается при другой активной личной программе, силовой истории перед первым импортом, неполной схеме или неактивной существующей программе A/B.
- Применяет миграции, программу и итоговые проверки одной транзакцией. При ошибке откатывает все изменения этого запуска. Не выполняет `DROP`/`TRUNCATE` таблиц и не удаляет историю.
- Не допускает параллельный запуск с другими скриптами миграции этого проекта; ожидание блокировок ограничено 5 секундами.

Скрипт меняет только базу. Для редактирования длительности в интерфейсе на сервере должна быть развёрнута версия приложения с полем `durationMinutes`.
