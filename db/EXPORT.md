# Экспорт для разбора

Приватная страница `/review/<ключ>` не добавлена в навигацию. Ключ — случайный
секрет минимум из 32 символов в серверной переменной `TRAIN_CLUB_EXPORT_KEY`.
Сама ссылка даёт доступ к экспорту. Без ключа или при неверном ключе страница
и `/review/<ключ>/download` возвращают 404. Ответы не кэшируются, запрещена
индексация и передача адреса в Referer. Ключ не попадает в JSON. Это защита
новой выгрузки, а не авторизация всего дневника: существующие API приложения
сохраняют прежнюю модель доступа.

## Использование

Кнопка «Экспорт для разбора» скачивает один JSON. По умолчанию — 84 календарных
дня включая сегодня (последние 12 недель). Можно выбрать всю историю или
произвольные начальную и конечную даты включительно. Вся история выгружается
без ограничения в 100 строк, включая записи с будущими датами, если такие
были внесены. Часовой пояс определяется браузером, его можно изменить. Даты
занятий — уже записанные календарные дни, без повторного пересчёта по UTC.
Недели начинаются в понедельник; пограничные недели могут быть неполными.

Содержимое JSON (`schemaVersion: 1`):

- `generatedAt`, `exportDate`, `timeZone`, `period` — момент и границы выгрузки;
- `units`, `rules` — единицы, трактовка источников и правила расчётов;
- `summary` — количество занятий и минуты по видам и неделям, даты, интервалы
  между залом, выполненные рабочие/разминочные подходы по упражнениям, последние
  три результата, попадание в план, сон/самочувствие/тяжесть и все заметки;
- `sessions` — все записи периода с ID, revision, createdAt/updatedAt,
  программой и её версией, сохранённым планом, источниками значений, упражнениями,
  исходными/фактическими заменами и всеми подходами с планом и фактом.

При объединении файлов одинаковый ID занятия учитывается один раз, берётся
максимальная `revision`. Для разных упражнений в одном занятии сохраняется
порядок `position`. `program.version` — версия программы, а
`queueRevisionAtSave` — служебная версия очереди; это разные величины.

## Достоверность

Для сна, частей времени зала, общей продолжительности бокса/пилатеса и обоих
значений пульса хранится источник: `user_confirmed`, `device`, `default`, `unknown`.
Ввод или изменение числа вручную отмечает `user_confirmed`; оставленное
предзаполнение — `default`. Кнопки подтверждения позволяют подтвердить число
без его изменения. Пустой сон/пульс сохраняется как `null`. В новых занятиях
пульс не предзаполняется. `pulseDevice` позволяет указать часы или другой
источник измерения; автоматического импорта с устройств пока нет. Значение
`device` предусмотрено для такого импорта, ручной перенос с часов остаётся
`user_confirmed` с названием часов в источнике измерения.

Миграция `004_export_provenance.sql` не угадывает источники старых чисел:
у всех старых записей и черновиков без признака источник `unknown`, даже если
число отличается от старого предзаполнения. Изменение заметки не подтверждает
сон, длительность или пульс. Неподтверждённый пульс в JSON представлен как `null`
с указанием источника и `unverifiedValuesOmitted`, а не как измерение.

`reportedMinutes` включает всё записанное время, `confirmedMinutes` — только
подтверждённое или полученное с устройства. Остальное вынесено отдельно;
есть суммы по источникам и счётчики неизвестной длительности. Смешанный
источник частей зала считается непроверенным для всей суммы. Нулевые значения
не подставляются вместо неизвестных фактов.

Новые занятия сохраняют полный снимок версии программы и всех вариантов
упражнений, включая исходное упражнение при замене. Исправление истории не
заменяет этот снимок текущим каталогом. Для старых занятий выбранные упражнения
и планы берутся из уже существующих снимков подходов. Опубликованные метаданные
программы неизменяемы и могут быть прочитаны из каталога; это помечено отдельно.
Если исходное упражнение старой замены не было сохранено, доступны его стабильные
ID, а утраченные название/оборудование/план остаются `null`, без подстановки
сегодняшних метаданных.

Сравнение группируется по ID упражнения, оборудованию, заметке о конкретном
тренажёре, единице результата, типу веса и признаку «на сторону». Вес одной
гантели и повторы на сторону не удваиваются. Если модель тренажёра не указана,
физическая идентичность тренажёра не гарантируется. Тоннаж, мышечные группы,
медицинские интерпретации заметок и выводы о восстановлении автоматически
не вычисляются. Интервалы между залом относятся к датам в выбранном периоде,
не являются часами отдыха и не исключают бокс или пилатес в промежутке.

## Развёртывание и проверка

Применить только миграции через `scripts/db.mjs migrate`, без очистки истории
и переключения программы. Миграция 004 не зависит от разрабатываемой миграции
003 следующего цикла и не занимает её номер. Формат поддерживает номера
тренировок 9–16 и диапазоны секунд, когда их предоставит следующий цикл.

Настроить `TRAIN_CLUB_EXPORT_KEY` в `.env.app.local` на сервере, не коммитить
значение и саму ссылку. Генерация: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`.
Пересоздать контейнер приложения после изменения переменной. Для отзыва
ссылки заменить ключ и снова пересоздать контейнер. Старая ссылка станет 404.

Регрессии в `tests/training-export.test.ts` проверяют границы дат, источники,
105 записей, снимки/замены/исправления, группировку нагрузки и пустую выгрузку.
В `tests/e2e/export.spec.ts` — авторизация ссылкой, скачивание JSON и подтверждение
значений без изменения числа. Для E2E нужно передать тестовый ключ одновременно
в сервер и тестовый процесс; CI использует отдельный, заведомо непроизводственный.
