# Train Club

Мобильный дневник тренировок: зал по очереди из 8 или 16 занятий, пилатес и бокс. React + TypeScript / Next.js, PostgreSQL, локальные черновики в IndexedDB. Интерфейс повторяет спокойную молочно-зелёную палитру [макета](design/README.md).

## Первая версия · 0.1.0

- Подготовка: календарная дата, самочувствие 0–5, сон.
- Зал: индивидуальный план каждого подхода, дробный или неизвестный вес, повторения и секунды, прошлые результаты, копирование предыдущего рабочего подхода.
- Одна дополнительная разминка, не уменьшающая рабочий план; допустимые замены со своими планами и историей.
- Замена доступна до ввода результатов. Для завершения нужны все рабочие подходы и добавленная разминка.
- Бокс и пилатес: изменяемая длительность в минутах (по умолчанию 60), пульс, тяжесть и заметка; очередь зала не меняется.
- IndexedDB сохраняет ввод и текущий экран после каждого изменения. Перезагрузка предлагает продолжить занятие. При ошибке сети черновик остаётся.
- Транзакционное завершение, защита от повторных запросов и конфликта очереди. Исправление истории с проверкой версии записи не двигает очередь.
- SQL-схема из восьми таблиц, исторические копии названий и планов, защита опубликованных программ от изменения.

Программа из `db/seeds/demo.sql` — повторяющийся **демонстрационный пример**, не программа тренера. Персональная программа A/B находится в `db/seeds/personal.sql`: 8 тренировок, 11 упражнений с учётом замен. В позиции №4 — сгибание ног сидя, замена — лёжа; по 2 × 12–15, отдых 60–90 секунд, запас около 3 повторений. Вариант с румынской тягой сохранён на случай отсутствия обоих тренажёров. Полный расширенный справочник и старые данные Google Sheets этим скриптом не импортируются.

## Локальный запуск

Нужны Node.js 24 и Docker.

```sh
nvm use
npm ci
cp .env.example .env.local
docker compose up -d --wait
npm run db:migrate
# Только для отдельной демо-базы; не выполнять поверх личной программы:
npm run db:seed:demo
npm run dev
```

Для персонального плана после миграций выполни `npm run db:seed:personal`. Скрипт активирует план в пустой базе или вместо демо без силовой истории, сохраняя демо-записи. Существующая личная программа или силовая история блокируют автоматическое переключение. Повторный запуск не создаёт дубликаты и не сбрасывает очередь.

`npm run db:migrate` применяет новые миграции и к ранее созданной базе. Миграция длительности сохраняет существующие значения 60 минут; она не создаёт запись пилатеса на 30 минут без даты и остальных данных.

Открой http://localhost:3000. PostgreSQL слушает только локальный интерфейс на порту 55439; данные сохраняются в Docker volume. `docker compose down` останавливает базу, не удаляя данные. Не добавляй `-v`, если данные нужны.

Без `DATABASE_URL` интерфейс открывается и позволяет готовить локальный черновик бокса/пилатеса; сохранение в дневник честно сообщает об отсутствии подключения. Локальный черновик не выдаётся за сохранённую серверную запись.

## Проверки

Цикл №9–16: [состав и загрузка](db/NEXT_CYCLE.md). `npm run db:seed:next-cycle` проверяет базу; `--apply` добавляет новую версию с неизменными №1–8 и шестью упражнениями в №9–16. После №16 очередь возвращается к №9.

Очистка всей истории занятий: [инструкция](db/CLEAR_HISTORY.md). `npm run db:history:clear` показывает количество записей; удаление выполняется только с `--apply`.

Засеивание рабочей базы: [инструкция и команды](db/PRODUCTION_SEED.md). `npm run db:seed:production` проверяет базу без записи; `npm run db:seed:production -- --apply` применяет миграции и план одной транзакцией.

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

Интеграционные тесты запускаются при заданном `TEST_DATABASE_URL`. Они **пересоздают схему** выделенной тестовой базы; её имя обязано оканчиваться на `_test`.

```sh
docker compose exec -T db createdb -U train_club train_club_test
TEST_DATABASE_URL=postgresql://train_club:local_development@localhost:55439/train_club_test npm test
docker compose exec -T db createdb -U train_club train_club_e2e_test
DATABASE_URL=postgresql://train_club:local_development@localhost:55439/train_club_e2e_test npm run db:migrate
DATABASE_URL=postgresql://train_club:local_development@localhost:55439/train_club_e2e_test npm run db:seed:demo
DATABASE_URL=postgresql://train_club:local_development@localhost:55439/train_club_e2e_test npm run test:e2e
```

E2E создают тестовые записи в базе запущенного приложения. Используй отдельную тестовую базу. CI автоматически поднимает PostgreSQL, проверяет типы, логику, транзакции, сборку и браузерные сценарии в Chromium и WebKit.

## Один собственный сервер: Next.js, PostgreSQL и Caddy

Рабочее приложение развёрнуто на одном сервере с Docker Compose, без Vercel и Supabase. Production-конфигурация — [compose.production.yaml](compose.production.yaml), сборка — [Dockerfile](Dockerfile). Порядок обновления, отката и восстановления описан в [инструкции эксплуатации](ops/DEPLOYMENT.md). Локальный Docker Compose из раздела запуска предназначен для разработки.

1. Подготовить сервер с Docker Compose и доменом. Настроить обновления, мониторинг, резервные копии PostgreSQL вне сервера и проверить восстановление.
2. Подготовить production-конфигурацию для трёх сервисов: Caddy → Next.js → PostgreSQL. Снаружи доступны HTTP/HTTPS через Caddy; порты приложения и базы не публикуются в интернет. Для PostgreSQL и сертификатов Caddy нужны постоянные тома. Передать `DATABASE_URL` в серверное приложение и среду миграций, используя внутреннее имя сервиса базы. Секрет не должен иметь префикс `NEXT_PUBLIC_`. Отсутствие входа в приложение не отменяет аутентификацию подключения к PostgreSQL.
3. Применить `npm run db:migrate` к выбранной базе. Загрузить программу тренера SQL-скриптом, начиная со статуса `draft`, затем опубликовать: триггеры проверяют число тренировок, основные варианты и планы.
4. Собрать production-образ Next.js на Node.js 24, запустить сервисы через Docker Compose и настроить HTTPS в Caddy. Порядок миграций и обновлений должен быть частью процедуры деплоя. Для тестового окружения использовать отдельную базу, не рабочий дневник.
5. Проверить Safari на настоящем iPhone: числовой ввод, безопасные отступы, блокировку, восстановление черновика, потерю сети и повторное сохранение.

GitHub содержит исходный код и запускает проверки. Обновления доставляются на сервер явно по инструкции эксплуатации; push сам по себе не выполняет deploy. База ежедневно копируется в зашифрованном виде, копии скачиваются на Mac раз в час, пока он включён, пользователь вошёл в систему и доступна сеть. Первое восстановление в отдельную тестовую базу проверено.

По согласованной архитектуре приложение **без входа**: любой, кому известен адрес развёрнутого приложения, может читать и изменять дневник. Запросы к PostgreSQL выполняет сервер приложения; браузер не получает реквизиты подключения. `noindex` не является контролем доступа.

## Текущие границы

- История показывает последние 100 занятий; пагинация — следующий шаг.
- Полноценная офлайн-загрузка приложения, синхронизация черновиков и управление программой через интерфейс не входят в первую версию.
- Конфликт очереди/редактирования не теряет локальные данные и показывается пользователю; автоматического объединения нет. Повтор с изменённым содержимым не считается сохранением старого запроса.
- Правила перехода на новую версию программы и работы с её старыми черновиками ещё не определены. До согласования не переключать программу при незавершённых занятиях.
- Загружена персональная программа A/B из восьми тренировок. История Google Sheets не импортирована.
- Используется технический HTTPS-адрес; собственный домен можно подключить отдельно.
- Проверки Chromium/WebKit пройдены; Safari на физическом iPhone требует пользовательской проверки.
- Автоматические копии вне сервера зависят от доступности Mac. Внешние уведомления о сбоях пока не подключены.
